# Contributor Guide

This document expands on the root `CONTRIBUTING.md`.

## Good First Areas

- Add tests for existing analysis modules.
- Improve report wording and templates.
- Add frontend empty and error states.
- Add small, transparent text pattern rules.
- Improve documentation for local development.

## Analysis Module Checklist

- Does the module explain its findings?
- Does it avoid claiming certainty?
- Does it include false-positive caveats?
- Does it keep evidence local unless the user explicitly configures otherwise?
- Does it include tests?

## Code Style

- Keep backend logic typed where practical.
- Keep route handlers small.
- Prefer structured findings over free-form strings.
- Keep frontend components focused and readable.
- Avoid visual clutter in the workspace UI.
